## 1. Rules carried into every feature

1. **Evidence basis on every link.** Values: `source_field` (a structured
   official field names the other record), `source_text_parsed` (an official
   element or heading such as `AUTH` or "AUTHORITIES:" holds free text; a
   versioned citation pattern parsed it; the exact wording is shown),
   `identifier_match` (two records carry the same official identifier, such
   as a RIN), `citation_in_text` (a full citation found at a locator in
   official text), `curated` (an owner-approved list). Nothing else.
2. **Closed label table.** Every link has a forward and a reverse label string
   from one table (`src/demo/link-labels.ts`), worded with the source's own
   heading where it has one ("Listed under 'Authority:' in 25 CFR part 900",
   "Source credit stated by the U.S. Code", "Shares RIN 1076-AF81",
   "Citation found at page 12"). A test fails on rendered text and exports
   containing: governs, applies, applicable, implements, authorizes,
   authorized by, under, eligible, eligibility (outside the existing Grants.gov
   filter wording), valid, binding, jurisdiction, good law, overrule, enacted
   by, supporting legislation, the law behind. No reverse listing for
   `citation_in_text` in 0.9 (that would be a citation graph we build).
3. **Citation patterns.** Only a full citation creates a link: title,
   code name and section (U.S.C., CFR, RCW, ORS, Idaho Code), Pub. L.
   congress-number, Stat. volume-page, FR volume-page, U.S. Reports
   volume-page. Short forms, "id.", "supra", "ibid.", "the Act", "section 4 of
   the Act" and a bare section symbol are shown as text with "short form, not
   resolved" and never linked to an earlier citation. "et seq." is kept as a
   range starting at a section and is never expanded. Fixture set per pattern
   covers the variants seen raw: "et. seq.", "P. L. 117-58", "Pub. L. 93-638"
   with an en dash, "5304(l)" (letter l), "609 U. S.", "C.F.R." followed by a section sign, Stat. page
   ranges. Each parse carries a pattern id and version.
4. **Deterministic browser, static indexes, no logging.** Suggestions and
   chain indexes are static files shipped with the page. No per-keystroke
   network call. No stored query history beyond user-saved follows and
   exports.
5. **Search words stay out of URLs and referrers.** Deep links carry the query
   in the fragment (`#q=`); the page sets a `no-referrer` referrer
   policy; the Worker accepts search terms in a POST body
   (GET kept for ResIST compatibility until it migrates); the page states that
   search words go to the named official services, which keep their own logs.
6. **Jurisdiction only from explicit evidence in the query.** Before any state
   matching, spans matching a name in the retained federal-recognition
   collection, a treaty title, or a case caption are masked. Full state names
   count; postal codes ("WA", "OR", "ID") count only next to a bill or code
   citation form; the English words "or", "id", "wa" never count. A bare bill
   number ("HB 1100") produces alternatives (Washington, Oregon, Idaho,
   Congress) with nothing chosen; the existing scope and state picker wins.
   Case names carry no jurisdiction unless the court is named.
7. **Positive allowlists for every new response shape**, applied before any
   Worker cache write, plus the D-068 personal-pattern guard on every quoted
   passage. No individual's name in any schema, fixture, artifact, export,
   config or document (reviewers are recorded as role or organization plus
   date).
8. **No model output in public output.** Jev and Parallel stay development
   tools (D-114). No vocabulary entry, alias, edge or label may come from Jev or
   Parallel notes; each needs an official URL read by a person or a raw fetch.
9. **Private material never leaves the machine.** Local documents live only in
   a separate local entry (`src/local-main.tsx`, built only by
   `scripts/build-policy-local.mjs`), code under `src/modules/private/`,
   resolved only against bundled static indexes, with no network call.

## 2. What a person sees

One page. Mode tabs: **Research** (default), **Grants**, **Tracking**, and
**Committee libraries** (only if a pilot library is approved, N5). The mode is
in the fragment, changes default panels and the export template only, never
filters by Nation or relevance, and does not re-run results.

A single search box. Exact identifiers and reviewed law names produce
suggestions in a WAI-ARIA 1.2 combobox ("Clean Water Act, 33 U.S.C. 1251 et
seq.", "25 CFR part 900", "Docket EPA-HQ-OW-2021-0602"). Choosing one runs that
lookup. Plain words run the existing multi-source keyword search, and the page
says "Searched as words". An ambiguous identifier shows its readings as choices.

Results group by family: Rules and notices, Laws and bills, Cases, Grants,
State, Intertribal publications. An opened document shows **Cited and linked
records**: sections for "Stated by the source" (`source_field`,
`source_text_parsed`), "Shared identifiers" (`identifier_match`), "Citations
found in the text" (`citation_in_text`), each row with its label, basis,
source, exact source wording where parsed, and retrieval time. Rows come from
the opened record and the static indexes; a family that needs a live call
expands only when the person presses it. Cases citing a law: "Not available
from an official source".

A **Sources** panel lists each source as: Enabled (verified at release
<date>), Enabled with a query outcome for this search (unavailable, rate
limited), Link out only, or Not covered, each with its coverage limit. Nothing
is called "live" without a current check.

A **Briefing** export (new template, from the same `buildDocument` output):
decision dates, source-stated changes since the person's last check, open
evidence gaps, and questions to take to staff or counsel, every item cited, no
recommendation and no legal conclusion.

## 3. Tier 1: core release candidate

### T1.1 Contract widening and boundary hardening (first, serial)

- Widen once, before parallel lanes: new source ids, match kinds, optional
  citation fields, source status model, the link and basis types, follow-kind
  registry, `FOLLOW_VERSION` 2 with migration of `ps-demo-following-v1`. Files:
  `src/demo/types.ts`, `validation.ts`, `search-contract.ts`, `citations.ts`,
  `merge.ts`; `src/demo/copy.ts` split into `src/demo/copy/<area>.ts`;
  `worker/src/index.ts` becomes routing plus a source registry with adapters in
  `worker/src/sources/*.ts` (behavior unchanged, existing tests green).
- Extract from `demo/main.tsx` only the seams the Tier 1 lanes need (search
  box, results family groups, document pane side panel, sources panel, export
  templates) into `demo/app/*.tsx`, with state hooks in `demo/app/state/`. Not
  a wholesale decomposition.
- Boundary: add `demo/main.tsx` and `worker/src/index.ts` to
  `PUBLIC_ENTRY_PATHS` and `demo` and `worker` to the scan roots in
  `tests/architecture/`; add `src/local-main.tsx` as the local entry; keep the
  enforcing reachability test green.
- ResIST compatibility fixtures for `/api/search`, `/api/policy`,
  `/api/sources` built from ATNI-ResIST's validators (read-only), plus a rule
  for adding enum values (new source ids and statuses appear only behind a
  version field ResIST can ignore). Coordinate with the ResIST lane before
  changing status values.

### T1.2 Query router and suggestions

- `src/demo/query-route.ts`, pure: readings for exact identifiers (docket, RIN,
  FR document number, FR citation, CFR, U.S.C., Pub. L., Stat., U.S. Reports,
  federal bill with Congress number, WA/OR/ID bill forms with number ranges:
  WA House 1000-2999 and Senate 5000-6999, Oregon House from 2001, Idaho
  H0123 and S1001 forms; RCW, WAC, ORS, OAR, Idaho Code, IDAPA citations) and
  reviewed law names; everything else is plain words. Dashed numbers return
  every source-qualified reading (FR document, RIN, Supreme Court or circuit
  docket with court code). Each reading maps to one action: live lookup,
  static index, link out, or not covered (table in the module).
- Reviewed alias table `config/law-aliases.v1.json`: about 150 Tribal-relevant
  federal laws by popular name with official U.S.C. citation and OLRC URL, each
  entry read from the official page; no Nation names, no Jev or Parallel
  provenance. The OLRC Popular Names HTML is not parsed (N7 optional later).
- Vocabularies: Federal Register agencies and topics (keyless API), the alias
  table, CFR title names. Built by `scripts/build-vocab.mjs`, a separate
  approved step outside `demo:build`, committed as a reviewed snapshot with
  checksums under the approved output (N18). Ceiling 400 KB gzipped.
- Acceptance: a blind set of at least 120 queries written from real staff
  tasks by an agent that has not seen the router, at least 4 per reading type
  plus the collision cases. Score: the correct reading is among the offered
  readings (top 3) in at least 95%; ambiguous inputs abstain (offer choices) in
  100%; zero jurisdiction from a masked span. Adversarial Nation-name probes
  are generated at test time from the recognition collection; no fixture file
  holds real Nation names. The 92-query prototype set is not committed.

### T1.3 Research chain, keyless

- At build time, on the approved conditions
  ([index conditions](full09-index-conditions-2026-11-05.md), D-125):
  - CFR part index from the official CFR annual edition on GovInfo (API with
    the current api.data.gov key at build time until D-123, or GovInfo bulk
    data for the same edition): part-level authority and source wording plus
    parsed citations, for a named set of titles (25, 36, 40, 43, 50 first; size
    measured and capped per title shard), labeled with the edition year.
  - eCFR as current reference and greater context: one request per title, its
    "up to date as of" wording shown beside the annual edition, used only after
    its terms are read (N17).
  - U.S.C. index from OLRC USLM per-title zips: per section, `sourceCredit`
    refs (`/us/pl/...`, `/us/stat/...`) with dates, and `reclassified_as` from
    `section@status="transferred"` plus the codification note's reference
    ("OLRC notes this section was editorially reclassified as 25 U.S.C.
    5321"). Shards per title under the approved output, loaded only when a
    title is opened. Titles 16, 25, 33, 42 (42 measured first; if over the
    shard ceiling, Tribal-relevant chapters only, stated on the page). Needs
    the OLRC download terms read (N17).
- At run time, from the opened record only: Federal Register `cfr_references`
  (labeled "CFR parts this document names"), `regulation_id_numbers` and
  `docket_ids` (`identifier_match`, reusing the existing Find related plan in
  `src/demo/discovery.ts`), `correction_of` and `corrections`
  (`source_field`), FR full-text `<AUTH>` when present ("No authority line in
  this document" when absent, never "no authority"). A pre-1994 FR citation in
  `SOURCE` shows "Not available from a live source".
- `citation_in_text` over text the page already reads (Federal Register HTML,
  Washington bill HTML), using rule 3.
- No keyed call loads automatically. GovInfo `/related` and Congress.gov
  related-bill families expand on click, cached in the Worker, one call per
  click, shown under "Stated by the source" with GovInfo's own relation name.
- Call and byte budget table in the module: per user action, keyed and keyless
  calls, worst-case bytes, cache, truncation behavior.

### T1.4 Grants: authority citations stated by the opportunity

- Keyless, existing host: Assistance Listing number and title from search2
  `cfdaList` and fetchOpportunity `data.cfdas[]` (`source_field`).
- Authority citations only when the Grants.gov synopsis itself has an
  "Authority" or "AUTHORITIES" heading (`source_text_parsed`), quoted with the
  opportunity URL and version date; otherwise "No authority passage in the
  retrieved Grants.gov record". Each U.S.C. citation links into the U.S.C.
  index (source credit). Agency PDFs on other hosts are out of 0.9.
- Allowlist: id, number, title, agency code and name, `cfdas[].cfdaNumber`,
  `cfdas[].programTitle`, open, close and forecast dates, docType, opportunity
  status; `synopsisDesc` goes only into the bounded passage extractor with the
  personal-pattern guard. Contacts, addresses, publisher ids and modification
  comments are dropped before the cache write.
- The page states the distinctions: forecast, posted opportunity, stated
  authority citation; appropriation, award, obligation and disbursement are
  not covered. The existing eligibility filter and `COPY.grants.limit` stay
  unchanged and are never on by default; the Grants.gov attribution sentence
  goes into every export.

### T1.5 Courts on existing hosts

- GovInfo USCOURTS search with `courtCode` (ca9, cafc, cofc, wawd, waed, ord,
  idd) and USREPORTS for U.S. Reports citations through volume 586 (one
  bounded live call confirms citation lookup before the route is called
  done). Case rows: case name, court, docket number with court code, date
  issued, official link, "citation not provided by this source". A U.S.
  citation above 586: "Not resolvable from an official source; search the case
  name." IBIA and Tribal courts: link out to the official IBIA search and to
  the NILL directory only (no per-Nation URL list).

### T1.6 Truthful sources and tracking

- Source model: `enabled`, `verifiedAt` (release verification receipt),
  `queryOutcome` (per search), `coverageLimit`, `freshnessPolicy`,
  `linkOutOnly`, `notCovered`. Safeguard 8 wording throughout.
- Tracking keeps the explicit "Check for new" model (never on page load, 50
  followed, 10 checks per press). Wording shows new, unchanged, not checked,
  unavailable, and no longer listed as distinct states, with last checked and
  source data-as-of. A new follow kind lands only with a defined identity and
  version key and a local baseline: first candidate `case` (GovInfo package
  id with court code; new means a new package or a changed `lastModified`).
- Consultation: a saved Federal Register search shown as "Documents containing
  these words", with the matched passage. Never labeled consultation notices,
  never naming a Nation.

### T1.7 Acceptance (staff tasks first)

For 0.9.1 the owner walks these tasks on the local build (an ATNI staff dry run
is optional); the formal outside-user test belongs to the 1.0 ratification. The
person completes each task unaided and explains what each result and link does
and does not establish:

1. Research: from a Federal Register rule to the CFR parts it names, the part's
   "Authority:" citation, the U.S.C. section (including a reclassification
   note), and its source credit (Pub. L., Stat.), exporting a cited result and
   a Briefing.
2. Grants: from a Grants.gov opportunity to its Assistance Listing and any
   authority citations its record states, and onward to a U.S.C. source
   credit, with the page's coverage statement.
3. Tracking: follow an item, press "Check for new", and read new, unchanged and
   unavailable states correctly.
4. An ambiguous bill number and a broad topic: the person sees the choices and
   understands what was searched.

Technical checks under those tasks: label-table test over rendered text and
exports; citation pattern fixtures; router blind set; call and byte budget
test; allowlist and personal-pattern tests; enforcing reachability with the
new entries; keyboard and automated accessibility on the combobox, mode tabs,
chain panel and sources panel; print view carries the chain; ResIST fixtures;
each live route's bounded call and trimmed synthetic fixture; `npm run check`;
sovereignty review before publication; owner approval of publication and each
Worker deployment.

### T1.8 Guards as automated checks, notices and freshness

- Every safeguard that can be tested is a test or validator that fails the
  check: the forbidden-label test, Nation-name masking probes generated from
  the recognition collection, positive field allowlists with the D-068
  personal-pattern guard, the private-entry reachability test extended to
  `demo/` and `worker/`, the static index validator (`validate:demo-index`,
  added to `npm run check`), and the source-boundary scan over
  `docs/demo-data/`.
- `THIRD-PARTY-NOTICES.md` is served with the page (copied into the Pages
  artifact by the demo build) and linked from the page footer.
- `scripts/check-index-freshness.mjs` reports when the index needs a refresh
  (new Congress or session, new public laws, executive orders, new CFR annual
  editions, a new U.S. Code release point). It runs at the start of each
  working session and in release preparation and changes nothing.
