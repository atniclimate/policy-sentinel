# H02 synthetic measurement protocol and results

This protocol precedes execution. Planning date: 2026-09-05. Root and both
independent reviewers approved the bounded design, not a performance outcome.
The adopted prompt hash and exact authority are recorded in
[the journal](PS09-ENGINEERING-REVIEW-02.md). No optimization is authorized.

## Prior protocol

Run `npm run measure:engineering -- --run` once, serially after focused checks
and implementation review. No other repository test, build or benchmark runs
concurrently. The command accepts no selectable corpus, source, URL, fixture,
size or output root. It creates an exclusive, owned `measurements-01` below
`I:/policy-sentinel-knowledge-assurance/2026-09-05/engineering-review-02`.
An existing output directory is refused. Historical roots are never inputs.

There are two families and six fixed cases: search at 100, 500 and 2,000 works;
knowledge at 5, 10 and 20 documents. Search fixtures have exactly one version
per work, four segments per version and at most 512 UTF-8 bytes per segment.
Each case has three warmups and ten measured repetitions. A case's total
120-second ceiling includes setup, correctness checks, warmups, measurements
and cleanup. The total ceiling is 20 minutes. Cumulative generated files are
limited to 10,000 and cumulative generated bytes to 256 MiB, including owned
Git and temporary/publication output. No fixture size increases or additional
measurement families are permitted. Incomplete cases remain incomplete.

Each fixed case runs in one owned child. Before production modules load, deny
network entry points independently and allow only the exact synthetic Git and
fixed native PowerShell child operations needed by the case. Parent launch is
limited to the same script and current Node executable, with an owned IPC token.
Synthetic Git uses fixed identity/dates and isolated configuration, disabled
hooks/signing, and no remotes. Record actual child invocations, not formula-only
estimates. Deadline handling must terminate and reap owned descendants before
cleanup; retain an incomplete owned root when termination or ownership cannot
be established. Never put timeout wrappers around file writes or locks.

### Correctness oracles established before timings

Build fixed synthetic v2 data directly, without importing a test module that
registers suites or includes unrelated setup. Validate and serialize/parse with
the actual v2 contract before search measurements. Pin deterministic input
bytes and expected output identities before comparing observations. Queries
cover exact identifier, quoted phrase, no match and empty query, with unfiltered
and all three temporal bases. Expected hit/version order, exact passage bytes,
capture/rendition/citation identities, and unknown/future/ambiguous time controls
must be independently derived from fixed fixture intent. A checksum alone is
not a semantic oracle. A failed oracle invalidates that case's timing claim.

Search phases separate validation, index construction, first query on a fresh
index, and warmed repeated query. Fresh index means an application cache reset;
it does not mean a cleared operating-system disk cache. Construction is outside
the first-query timer and separately measured. Observe the same query cases
through three warmups and ten measured repetitions, retaining all observations.

Knowledge uses fixed, owned synthetic Git repositories and the actual
validateKnowledge, buildNavigation and publishKnowledge functions. Verify
expected navigation links/content and output hashes independently before
timings. Setup creates the first publication; measured publication replaces
that owned output. Separate validation, navigation, replacement publication
and total generation. Count actual Git and PowerShell calls and retain the
project-namespace scope: generic synthetic projects do not prove the extra
Policy Sentinel custody-reference path or real document acceptance.

### Provisional targets and reporting

Targets selected before results: at 2,000 works, warmed search-query median
at most 100 ms and index-construction median at most 1,000 ms; at 20 knowledge
documents, total generation median at most 10,000 ms. These are provisional
engineering targets, not user acceptance or release criteria. Report misses
without changing the target after observation. No p95/p99 or tail guarantee
can be derived from ten measured repetitions.

Record all warmup/measured observations, median/minimum/maximum, phase and wall
time, hardware/OS/runtime, fixture counts/bytes, exact input/output/code hashes,
and measured instrumentation overhead. Label process memory as sampled RSS
unless a true high-water mechanism is verified; samples are not a peak-memory
bound. Report empty timing-envelope and child-count-wrapper overhead separately.
Unrelated machine load is not controlled, and no causal bottleneck or speedup
claim follows merely from a small local timing series.

## Pre-execution implementation clarification

The implementation retains its bounded owned synthetic case roots as evidence,
including normal results. It performs no recursive case-root deletion. On a
timeout it addresses only its owned Node ChildProcess; native descendant
termination remains unconfirmed unless independently established. Missing or
invalid budget handoff, deadline violation or unconfirmed reaping stops further
cases and leaves the result incomplete. A five-second reap allowance is reserved
inside the case ceiling; it is not an extension after 120 seconds. Completion
also checks monotonic elapsed time so delayed timer dispatch cannot admit a late
nominal success. The final report separately labels supervision wall time and
post-case inventory/persistence rather than presenting a file-write timeout as
safe cancellation. The owned final report write is awaited.

Before the first run, independent review requires exact semantic edge/navigation
and source-limitation checks, search hit/total/method/citation/temporal controls,
and malformed accounting/deadline fixtures. Hashes are pinned only after those
semantic oracles pass. Setup is separately timed; wrapper overhead must include
the reported scope or be explicitly labeled as policy-check overhead. These
clarifications change no family, size, repetition, target or resource ceiling.

A second pre-execution closure requires the oracle's expected passage presence,
count and identities, not merely validation of whatever passages were returned.
The fixed cases request four passages, matching their four authored segments.
On incomplete/unconfirmed supervision, only the already owned ChildProcess/IPC
references may be disconnected/unreferenced so they cannot unnecessarily keep
the parent alive. Both reviewers approved that bounded correction with repeated
late-error observation and immutable incomplete results. Detachment does not
establish child/descendant termination or permit deletion of retained roots.
