## Phase gates, acceptance, and stop contract

1. Candidate lifecycle schema/runtime/tests must address every pre-freeze
   counterexample; byte-level adversarial approval freezes version 1.0.0.
2. Current primary evidence plus the Tier-1 parser/transport must support the
   exact operation. An incompatible term, required account/key/fee/clickthrough,
   reproduction conflict, or material privacy ambiguity blocks the source.
3. After qualification, a fresh source/security/sovereignty review must approve
   exact request and lifecycle bytes before conditional local activation.
4. One acquisition is parsed/transformed twice from the same sealed bytes; raw
   bytes are removed. The normalized ignored revision is replayed twice through
   the corpus/artifact builder with byte-identical declared inventories.
5. Genesis, no-prior failure, compatible stale LKG, corrupt/cross-source/
   cross-contract/cross-range/future/expired/partial rejection, atomic promotion,
   and source-isolated recovery pass.
6. The built local site exposes only general federal records, zero Nation
   associations, exact provenance, honest coverage/health/expiry/limitations,
   same-origin details, safe CSV/dossier, and no provider runtime call.
7. Focused security/accessibility/browser evidence and a final integrated
   adversarial review pass; one terminal serialized `npm run check` passes.
8. Owner inputs remain byte-identical and unreachable; default `npm run build`
   remains synthetic and network-free; no raw/generated real data enters Git.

Stop the whole run for an excluded external action, owner-input conflict,
credential/account/clickthrough/payment/contact requirement, private/sensitive
material, remote/publication action, material North-Star change, unresolved
sovereign-authority ambiguity, or unrepairable high-severity integrity defect.
A Federal Register-specific evidence failure blocks only its qualification,
refresh, and application branch; generic lifecycle/corpus/security work and the
portfolio review continue.
